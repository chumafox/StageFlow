# ADR-003: Transport Model and Audio Clock Synchronization

- **Статус:** Принято (Approved)
- **Дата:** 2026-11-02
- **Автор:** AI Pair Programmer & Audio Architecture
- **Контекст:** Решение проблем SF-04, SF-05; надёжный транспорт и устранение рассинхрона между звуком, индикатором времени и суфлёром.

---

## 1. Проблема

В исходном коде (`d48ee50`):
1. Метод `seek(to:)` менял только переменную времени в UI, не меняя позицию в `AVAudioPlayerNode`.
2. Метод `stop()` перезапускал зацикленный procedural demo buffer вместо выбранного пользовательского файла.
3. Время воспроизведения прибавлялось системным `Timer` с шагом `+0.05с`, что вызывало неизбежный тактовый дрейф от реального аудио-рендера.
4. По окончании файла плеер зацикливал таймер в UI, тогда как звук прекращался.
5. Выбор трека в плейлисте мог не сбрасывать статус `isPlaying` при остановке ноды.

---

## 2. Архитектурное решение

### 2.1. Конечный автомат транспорта (Transport State Machine)
Вводится строгое перечисление состояний:

```swift
public enum TransportState: Equatable, Sendable {
    case stopped
    case loading(URL)
    case ready(URL)
    case playing
    case paused
    case ended
    case error(String)
}
```

- **Stopped:** Аудио-нода остановлена, позиция = 0.0, буферы очищены.
- **Loading:** Чтение аудиофайла, вычисление точной длительности и формата в фоновом потоке.
- **Ready:** Файл успешно расписан в плеере с начального фрейма (или после Stop), готов к старту.
- **Playing:** Плеер реально воспроизводит звук, аудиочасы инкрементируются. Индикатор `ON AIR` активен.
- **Paused:** Воспроизведение приостановлено, текущий фрейм сохранён, позиция зафиксирована.
- **Ended (EOF):** Файл доиграл до конца. Воспроизведение останавливается, плеер переходит в `ended`, позиция = duration (или 0.0 по настройке), `ON AIR` выключается.
- **Error:** Ошибка загрузки или старта движка; отображается пользователю.

### 2.2. Запрет неожиданного автозапуска (No Autoplay on Selection)
- При выборе трека в плейлисте файл загружается, статус переходит в `.ready`.
- **Воспроизведение НЕ начинается автоматически.** Запуск возможен только по явному действию пользователя (нажатие `Space`, кнопка Play, педаль MIDI).

### 2.3. Достоверный Audio Clock
- Реальная позиция воспроизведения вычисляется на основе аппаратных часов CoreAudio:
  ```swift
  guard let nodeTime = playerNode.lastRenderTime,
        let playerTime = playerNode.playerTime(forNodeTime: nodeTime) else { ... }
  let currentTime = Double(playerTime.sampleTime) / playerTime.sampleRate + startOffsetTime
  ```
- Системный таймер (20-30 Гц) используется **исключительно для опроса (polling) и перерисовки UI**, а не как источник инкремента времени!

### 2.4. Поведение Seek и Stop
- **Seek(to: targetTime):**
  1. Вычисляется целевой фрейм: `targetFrame = AVAudioFramePosition(targetTime * sampleRate)`.
  2. Если трек играл, плеер временно останавливается, сегмент планируется начиная с `targetFrame`:
     `playerNode.scheduleSegment(file, startingFrame: targetFrame, frameCount: remainingFrames, at: nil, completionHandler: ...)`
  3. Если плеер был на паузе, он остаётся на паузе; если играл — возобновляет воспроизведение.
- **Stop():**
  1. Нода останавливается `playerNode.stop()`.
  2. Файл перепланируется с нулевого фрейма (`targetFrame = 0`).
  3. Состояние переводится в `.stopped`. Никаких синтетических demo буферов не подставляется!
